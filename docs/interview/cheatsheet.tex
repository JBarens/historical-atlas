\section{Facts I got wrong in round 1}
\begin{itemize}
\item It \textbf{never} answers from training data: no evidence $\to$ \texttt{insufficient\_evidence}.
\item Corpus = Commons \textbf{and} Lords (Hansard) \textbf{plus} FRUS, not Lords only.
\item Headers make retrieval \textbf{find} names and dates (lexical), not ``more efficient''.
\item CI: fast gate on \textbf{every push}; full eval \textbf{manual} or forced by an LLM-contract change. Not daily.
\item Cost is \$0.012 per question, not \$0.0012.
\item Code: \textbf{nearly 100\% AI-generated}. Say it; own the decisions.
\end{itemize}

\section{Answer pattern}
Problem $\to$ approach $\to$ proof (a number) $\to$ one trade-off or lesson. Answer the question asked. Use ``I decided''.

\section{1. Two-minute pitch}
\ans{Researchers need answers they can verify, and general LLMs confidently make things up on niche history. I built
grounded question answering over $\sim$5,000 parliamentary speeches and US diplomatic documents on five League of Nations
disputes: hybrid retrieval (BM25 for names and dates, dense embeddings for meaning), a Haiku reranker, and a
deterministic inflation tool. Every claim cites a source passage; without evidence it declines. On a held-out test set I
opened once: correctness 0.80 (95\% CI 0.68--0.93), faithfulness 0.98, p95 5.4 s. Retrieval is the ceiling: with the right
passage, 19 of 19 answers were correct.}

\section{2. Why not put everything in the context window?}
\ans{It doesn't fit: 1.3M tokens against 200k. Even if it did, about \$1.30 a question against \$0.012, roughly 100$\times$,
and tens of seconds per question. Caching cuts input cost $\sim$90\% but expires and doesn't fix size; long inputs also lose
detail in the middle. With a 50-page corpus I'd skip RAG and cache the whole thing.}

\section{3. You wrote the questions: why trust 0.80?}
\ans{Fair, it's the main limitation: questions were LLM-generated from the documents, so more lexical than real users,
which flatters retrieval. A held-out test stops tuning overfit, not construction bias. Mitigations: verbatim passages
verified against source; judge only used after matching my grading $\geq$8/10 (v1 failed at 5/10); results reported by
question source. Real fix: independent questions from users or a historian.}

\section{4. Something that went wrong}
\ans{The live API was still calling the day-one code while I evaluated a different pipeline: every number described a
system no user could reach. I wired the API to the evaluated pipeline; now CI runs the same path and a prompt or model
change can't merge without a full eval. Alternatives: judge 5/10; split model = retriever (leakage); calculations 8/12.}

\section{5. 2,000 employees: cost and what breaks}
\ans{About a cent a question: \$700--3,600 a month depending on adoption (5 a day, 22 workdays); validate in a pilot from the
request logs. Peak $\approx$60 questions/min $\approx$150 API calls/min, so size the API tier above peak; a queue only grows while
arrivals exceed capacity. What breaks first is the enterprise wrapping: SSO instead of invite codes, rate limits in Redis
instead of memory, a log retention policy legal signs off.}

\section{6. What did you actually do?}
\ans{Almost all code was AI-generated; my job was judgment. I caught the split model leaking into the eval, hand-graded
the judge (5/10) and wrote its rubric, made code route calculations to the tool (8/12 $\to$ 11/12), chose BM25 over
Postgres FTS on measurement, set the release thresholds, chose top-20 rerank (41\% cheaper). Delegated drafting is
documented and reported separately.}

\section{Other lines worth having}
\begin{itemize}
\item \textbf{Containment over detection:} a detector false-positives on history questions and doesn't cover documents.
\item \textbf{Security lesson:} grounding stops instructions in documents, not false facts; at a client, ingestion is the boundary.
\item \textbf{Scale:} LLM cost per question doesn't grow with corpus size; local retrieval does (BM25 18$\times$ at 10$\times$ data).
\item \textbf{Postgres:} at 10k chunks, even 10$\times$, one system is simpler; I'd move for lexical quality before vector scale.
\item \textbf{Logs vs metrics vs traces:} what happened in this request / is the system healthy / where did time go.
\item \textbf{p95 doesn't add} across stages: measure end to end.
\end{itemize}
